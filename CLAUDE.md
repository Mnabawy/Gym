# GymApp
App name GymApp (expo `name` `GymApp`, slug `gymapp`, package `com.mnabawy.gymapp`, scheme `gymapp`; a separate app from Brainy, sharing none of its ids or services). Personal workout + nutrition app for one user, gym only: workout, food, shopping, program, progress, weight. Arabic UI, RTL, Egyptian dialect copy.
Exercise names stay in English (gym vocabulary).

## Stack
- Expo SDK 58, TypeScript strict, expo-router (routes in `src/app/`, tabs in `src/app/(tabs)/`, the gym's three pages in `src/app/(tabs)/(gym)/`)
- State: zustand (`src/lib/timer.ts`, `src/lib/bus.ts`)
- Storage: expo-sqlite on iOS/Android (`src/lib/storage.ts`). Android-only app; web is not a target (no web build, no `.web.ts` files)
- expo-haptics, expo-keep-awake, expo-notifications (rest timer when backgrounded, workout reminder, morning brief), expo-clipboard, expo-file-system + expo-sharing + expo-document-picker (backup file), expo-image-picker + expo-image-manipulator (progress photos), react-native-webview (form videos play in-app)
- Fonts: Apple's system font (SF Pro + SF Arabic on iPhone; sans-serif on Android): `F` + `font(w)` in `src/theme/index.ts` give fontFamily + fontWeight (+ tabular digits for `num*`); `T` uses it. No custom fonts are loaded
- Offline-only: everything is saved on the phone (SQLite). No accounts, no cloud sync: backup files (and the weekly automatic copy) are the way data leaves the phone.

## Design rules
- RTL forced (expo-localization plugin `forcesRTL` + I18nManager in root layout). Use `start/end`, never `left/right`.
- One fixed color per muscle (Okabe–Ito, colorblind-safe) in `src/theme/index.ts`.
- Technique tags: تقيل (filled), فشل (outlined), دروب (dashed). Copy in `src/data/rules.ts`.
- Food chip colors: protein blue, carbs orange, fat green, veg grey.
- Apple look app-wide: iOS system colors in `src/theme/index.ts` (grouped grey background, white cards, no shadows, hairline separators, system green switches, tinted/filled buttons, plain tint header icons), tight spacing (cards radius 12, page gap 8, rows 44pt). `warm` / `warmDark` are now the same as light/dark.
- App color: Apple's black and white, chosen by the owner (Nov 2026): `t.ok` #1C1C1E on the light theme, #F2F2F7 on the dark one (`onOk` the opposite; `okSoft` #DCDCE0 / #3A3A3C). Content on `t.ok` uses `t.onOk`, on `t.ink` uses `t.onInk`, never a fixed white. Surfaces that are dark in both themes (the rest timer bar) use the dark theme's white (`ON_BAR` in TimerBar.tsx). Section colors (`t.sec`), macro and priority colors stay. The «لون التطبيق» setting was removed on the owner's request (Nov 2026): `useTheme` no longer reads settings `accent` (the field is still parsed, stored and synced, unused) and AccentPicker / accentTokens are gone.
- Dark mode follows the phone (`userInterfaceStyle: automatic`): `useTheme` picks light/dark tokens; `AppTheme` in the root layout gives the navigators the same colors (expo-router `ThemeProvider` with Dark/DefaultTheme + our bg/card/text/line) and sets the root background (`expo-system-ui` `setBackgroundColorAsync(t.bg)`), so no light frame shows between pages or behind the keyboard in dark mode. Use theme tokens for anything that sits on the page; fixed colors only on purpose (white text on color fills, the dark quit «night» card, weight-plate colors)
- Gym only (Nov 2026): this copy was cut down from Brainy to its gym. Gone, with their tests and packages: tasks, goals, habits, adhkar, quits, money, focus, brain dump, ideas, the home page (يومي / أسبوعك), the calendar, Supabase sync, Google sign-in (welcome and account pages), prayer times, the Quran verse popup, the app lock, cardio, phone steps, the gaps report and the weekly report. Don't bring them back unasked. `/` redirects to `/workout` (`src/app/index.tsx`). Brainy meta keys in a restored backup are kept but unused (its phone-only ones are listed in `src/lib/metaKeys.ts`); reminder.ts still cancels notification kinds Brainy scheduled (`OLD_KINDS`). Bottom tab bar: `src/components/TabBar.tsx` (`tabBar` on `src/app/(tabs)/_layout.tsx`), one tab الجيم for now. A floating capsule over the page, icons only (24pt), no animation: 54pt high, 36pt from the sides, just above the system navigation bar (`src/components/tabSpace.tsx`); see-through card color with a hairline and a soft shadow; open tab = filled icon on a soft `t.ok` pill. It slides away (200 ms) while you scroll down and comes back when you scroll up (`useBarHidden`, `useHideOnScroll`; `Screen` wires its ScrollView). Pages leave room for it through `useTabBarSpace()`; a `footer` (the rest timer on the workout) floats just above the bar and follows it down when it hides. The gym's التمرين (`/workout`) · الأكل (`/food`) · المشتريات (`/shop`) are a tab navigator without a bar (`src/app/(tabs)/(gym)/_layout.tsx`, opens on the workout) switched by `GymSwitch` in `src/components/GymSwitch.tsx`, an iOS segmented control at the top of each of the three pages (the same file has the plain `Segmented` control used in sheets). Detail pages stay in the root stack, above the tabs
- Motion: react-native-reanimated + react-native-gesture-handler (`GestureHandlerRootView` in the root layout). `src/components/Motion.tsx`: `Item` (list item fades/slides in, fades out, the rest glides into place; used for meals, extras, shopping items, exercises, weights), `Fade` (page content in `Screen`), `Press` (shrinks under the finger; `Btn` uses it), `Pop` (zooms in a checkmark). Don't use `withInitialValues` on entering animations (they stay hidden on web). Screens push iOS-style on both phones, swipe back from anywhere on iPhone. Reanimated follows Reduce Motion
- Swipe actions only on items that have real actions (`src/components/Swipe.tsx`, hand-built on gesture-handler v3 `usePanGesture` + reanimated; not ReanimatedSwipeable, which measured its panels wrong on Android RTL): `start` actions at the start/right edge (drag toward the left), `end` at the left edge; 72pt actions (narrower when a side has many, so an open panel covers at most 82% of the row and part of the row stays to tap or drag back), first one outermost; past half the panel it stays open, a full swipe runs the side's first action (only when that side's panel is under half the row); one row open at a time, tapping an open row closes it; iOS action colors `ACTION`; destructive ones undo or confirm. Used on exercises and sets, meals, extras, supplements, shopping items, weights, program exercises. No swipe on rows whose only action would be «افتح» (side menu, settings). Modals need their own `GestureHandlerRootView` (`Sheet` has one)
- Light + dark from one token file. Segmented controls (MiniSwitch, the gym switch) use `t.segBar` / `t.segOn` (iOS: white on grey in light, #636366 on a grey track in dark). Touch targets ≥ 44pt.
- Small font app-wide: `T` (`src/components/ui.tsx`) draws every size × `TEXT_SCALE` (0.9). Write sizes at full scale; tight spacing (`Screen dense`) on the workout, food and shopping tabs.
- Every delete button is red: `Btn kind="danger"` (red on soft red; `dangerSolid` for the final wipe and danger confirms), trash/✕ icons in `t.bad`.
- Every `TextInput` style starts with `INPUT` (ui.tsx): on Android it drops the field's vertical padding and font padding, which cut Arabic text off while typing with the system font.
- One button size: `Btn` (40pt, one line of 14pt text that shrinks to fit) — use it for every text button. `T` caps the phone's font-size setting at ×1.15 (`maxFontSizeMultiplier`).
- Section colors `t.sec` (iOS system colors) only for small marks (icons, rings)
- The neon workout-tab mode was removed. `t.neon` now only means the bordered warm look (thin borders, `glow()`).

## Data
- `src/data/program.ts` — the 4-day program (`PDF_PROGRAM`; the PDF's 5 days, with its two leg days merged into one «رجل وسمانة», id 3, in Nov 2026 on the owner's request; the old quads day id 6 and the dropped exercises live on in `RETIRED_DAYS` / `RETIRED_EXERCISES` so old sessions keep their names, `dayTitle`). The exercises can be edited in the app (`/program`, from settings: add, delete, reorder, rename, reps, technique, replace; `src/lib/programEdit.ts`, meta `program`); `applyProgram` puts that edit into `PROGRAM` / `ALL_EXERCISES` / `DEFAULT_SETS` in place, then `applyPlan` writes the settings' sets overrides and rest, so every screen reads the same plan. The base's program days themselves are fixed (their ids are stored with logged sets); a generated plan (below) replaces the base. Renaming keeps an exercise's id (and history); replacing makes a new id
- Generated plans (Nov 2026, the product direction: beginners and intermediates): `/setup` (`src/app/setup.tsx`; opens by itself the first time with nothing logged, `needsSetup` + meta `setupDone`; also settings «ابني برنامج جديد») takes goal (عضل / قوة / تنشيف), level (مبتدئ / متوسط) and 3–5 training days; `src/lib/generator.ts` `generate` builds a full body / upper-lower / push-pull-legs plan from the library (the PDF's and retired exercises, each with a video and alternatives; no exercise twice). It's saved as meta `template` (`src/lib/template.ts`) and `applyBase` (program.ts) makes it the base program in place of the PDF (`BASE_PROGRAM` / `BASE_TITLES`; edits in meta `program` start from the base; `PLAN_WEEKDAYS` = its training days). Generated day ids start at 100 and are never reused (`nextDayId`); days you left keep their names in meta `pastDays` (`PAST_DAYS`, `dayTitle`). `settings.setTemplate(t | null)` switches (null = back to the PDF, from settings)
- `src/lib/settings.ts` — settings store (zustand), saved as JSON under storage meta key `settings` (a save writes only the fields that changed, unknown fields kept) plus phone-only meta `device` (`DEVICE_SETTINGS`: backupDir, keepAwake, haptics; moved out of `settings` on start when `device` is missing; restoring a backup keeps this phone's `device`)
- `src/lib/energy.ts` — calorie/macro calculator (`/calories`, from the side menu or settings); formulas and sources at the top of the file. Once it has your data, `targetsFor` makes its numbers the food tab's daily targets instead of the plan's `TARGETS`
- `src/components/SideMenu.tsx` — ☰ on the gym tab headers: animated side menu with التقدم في الجيم، وزنك والقياسات، الإعدادات
- `src/lib/gaps.ts` — training-gap analysis (deload due: `deloadDue`, the light-week card on the workout tab; `prSet` / `toSessions` for records); thresholds and their sources are at the top of the file. حساب السعرات is opened from settings and the weight page
- `src/lib/shop.ts` — splits the weekly shopping list into N trips (settings) with equal item counts; items are never split, few-day items go on the trip before they're eaten (`assignTrips`). The list itself is fixed; the trip chosen for any item (`shopMoves`) lives in settings and is edited from the shopping tab's edit button
- `src/data/nutrition.ts`, `src/data/shopping.ts` — generated from the nutrition plan / shopping list PDFs
- Food tab training vs rest day isn't the PDF's fixed weekdays (`WEEK_MENU.training` is unused): `isTrainingDay` in `src/lib/schedule.ts` — a day with a logged workout is training, a past day without one was rest, today counts as training unless switched to rest from the food tab (meta key `restDay`)
- `src/data/videos.ts` — one short YouTube form video per exercise ("فيديو" button on each exercise card opens `VideoSheet`, which plays it in-app); how they were picked is at the top of the file
- Source PDFs live in `docs/`
- Config: `eas.json` holds build profiles only; there are no env values or secrets in the repo
- Build identity: `app.config.js` extends app.json (keep config there) and adds `extra.build` = git short SHA ('dev' without git) + build date; `src/lib/buildInfo.ts` (`BUILD`, expo-constants, safe fallbacks) shows it at the bottom of settings and backup files carry it as `build: { version, sha }`
- Crash safety net: `src/components/CrashScreen.tsx` (`crashBoundary(where)` = expo-router `ErrorBoundary` export on the root layout and the tabs layout; minimal on purpose: fixed light/dark tokens, no settings or storage read; «جرّب تاني»، «انسخ التفاصيل»، «الإعدادات») + `src/lib/errlog.ts` (`report(e, where)`, never throws: last 50 errors in phone-only meta `errLog`, a repeat of the newest is counted; called from the crash screen, auto backup, reminders); settings «سجل الأخطاء» (`src/components/ErrLogRow.tsx`: list, copy all, clear)
- `src/lib/backup.ts` (format, parsing) + `src/lib/backupIO.ts` (share sheet, file picker, clipboard) — backup and restore of everything (`Storage.dump` / `restore`), from the settings page; `src/lib/restore.ts` `applyBackup` is the one way to put a file back (a safety copy first, `src/lib/safety.ts` / `safetyIO.ts`; keeps this phone's `device`). Meta `lastBackup`; the end-of-workout card nudges after 7 days
- `src/lib/weight.ts` — body weight log (`/weight`, side menu وزنك), meta `weights`; weekly rate vs the goal. Logging a weight also sets the calculator's weight
- `src/lib/journal.ts` (pure) + `src/lib/meta.ts` (read/write) — JSON maps in meta: `swaps` (exercise swapped for today, `date|exId` → name; sets stay on the program exercise, records/prefill/progress chart only compare the same variant, `toSessions` gets the swapped set), `notes` (per exercise), `water` (ml per day), `mealPicks` (meal option per `date|meal`); food history for the food tab
- `src/data/alternatives.ts` — swap alternatives per exercise
- `src/lib/plates.ts` — plate calculator (which exercises use a bar, bar weight `barKg` in settings)
- `src/lib/summary.ts` — end-of-workout summary card (volume, change from last time, records, session length from set tick times)
- Workout flow: ticking an exercise's last set opens the next unfinished one after it in the program's order, else one skipped before it (`nextToOpen` in `src/lib/workoutFlow.ts`; with `askRir` it stays open until the RIR question is answered: `ExerciseRow` `onChange('hold' | 'done')`). Today's workout turning finished while the screen is open (any last tick: open card, summary row, RIR answered or not; `wasDone` in workout.tsx) opens `src/components/WorkoutDonePopup.tsx` («خلصت التمرين», what's next, a quote): a hadith and a fact by turns (`quoteFor`, data in `src/data/workoutQuotes.ts`, indexed by sessions logged)
- Exercise card: tapping the name of an open card (or a long press on any) copies it (expo-clipboard, «اتنسخ ✓» for a moment). Under each set a grey line «آخر مرة 60×8 · أعلى 65 كجم» (`setHint`: last session's numbers for that set + `bestBySet`, the heaviest done weight on that set number before today, same variant). The rest bar (`TimerBar`) slides in with a Reanimated `entering` animation, not an RN Animated opacity (that one could stay at 0 and hide a running rest)
- Auto progression: `src/lib/progression.ts` (`progressFor`, double progression from the last two sessions of the same variant, `recentFor` in journal.ts): top of the range or RIR 3+ on every set → +`weightStep` and back to `repLow`; in the range → +1 rep per set; below the range once → hold; twice at the same weight → −10%; light week → repeat. Its per-set targets prefill unticked sets (`suggest` gets them instead of last time); the chip on the open card (+2.5 ↑ / +1 تكرار / خفّف ↓) opens why. Settings `autoProgress` («زوّد الأوزان تلقائي», on by default) turns it off: sets start from last time's numbers, no chip
- First session: the workout tab shows «أول تمرين ليك» (`FIRST_WORKOUT_TIPS` in progression.ts) all day on the first day you train; an open exercise you've never done (as this variant) shows `firstTimeHint` (pick a weight you could do the top of the range with 2–3 reps left)
- Set rows also store `rir` (reps left, asked after each tick when `askRir` is on; `increaseTip` in logic.ts suggests more weight at RIR 3+) and `at` (tick time, ms; null for past days)
- Migrations. SQLite schema: `src/lib/dbMigrations.ts` `SCHEMA_MIGRATIONS`, keyed by `PRAGMA user_version`, each run in a transaction with its bump from storage.ts `setup` (so dbOpen.ts recovery still sees the raw error: only corrupt files move aside). Migration 1 = the whole old schema, idempotent (`addColumn` checks `PRAGMA table_info`). One-time meta changes: `src/lib/metaMigrations.ts` `META_MIGRATIONS`, run once at start by storage.ts, counted in meta `metaVersion` (phone-only; goes in backups, so each must be safe to run again); empty so far. To add either: append a function at the end, never edit or reorder a shipped one, add a case in `__tests__/storageContract.test.ts`. Fixes that must also apply to restored data (the `device` split in settings.ts `load()`) stay where they are
- Workout tab can log or fix a past day (calendar button, last 14 days): sets go to that date, the rest timer stays off. Food tab can tick meals, water and supplements for earlier days of the week
- `src/lib/plates.ts` also has `warmups` (warm-up ramp for heavy-tagged exercises, "إحماء" on the exercise card)
- `src/lib/weight.ts` also has body measurements (meta `measures`); `src/lib/photos.ts` (expo-image-picker, shrunk with expo-image-manipulator, files in the app's document folder; in the backup file as base64 — "احفظ نسخة" and the automatic copy in your folder, not the clipboard copy or the in-app auto copies; restore adds missing ones) — both on `/weight`
- `src/lib/journal.ts` also has food outside the plan (meta `extras`) and supplements ticked (meta `supps`)
- `src/lib/foodStore.ts` — the food tab's only write path (meals, water, supplements, extras, meal picks, rest day); each action returns its undo (an inverse that touches only what it changed). Writes to more than one key go in `atomic` (`src/lib/atomic.ts`, one storage transaction; nested calls join it)
- Deleted exercises keep their history: `pastExercises` meta (id → name, muscle; written by `setProgram`), `exerciseInfo` in programEdit.ts; the progress page lists them under "اتشالت من البرنامج"
- `src/lib/autoBackup.ts` — weekly automatic backup (last 4 inside the app, plus a folder you pick with `Directory.pickDirectoryAsync`, settings `autoBackup` / `backupDir`); runs from the root layout; skipped only when `hasData` is false (meta-only data counts); the in-app copy goes through `writeVerified` (`src/lib/verifiedWrite.ts`: .tmp → read back and compare → rename, shared with the safety snapshots in safetyIO.ts) before old copies rotate out and `autoBackupAt` is set; the folder copy is read back and checked before it counts as `lastBackup`. `DATA_KEYS` in backup.ts = the meta keys that hold logged things; `isLocalMeta` (`src/lib/metaKeys.ts`) = phone-only keys
- `src/lib/dbOpen.ts` — storage.ts opens gym.db through `openWithRecovery`: a broken file is renamed `gym.db.broken-<ms>` (with its -wal / -shm, never deleted), a fresh one opens (in-memory if even that fails), and phone-only meta `dbRecovered` notes it; settings shows a line above the backup buttons until «تمام». `__tests__/storageContract.test.ts` runs the Storage cases on the real storage.ts over `node:sqlite` (`test-utils/nodeSqlite.ts`)
- `src/lib/reminder.ts` — workout reminder and morning brief notifications (settings `reminder*`, `brief`, `briefTime`; `reminderDays` = your training days for both), next week scheduled ahead (`reminderTimes` in schedule.ts), re-synced from the root layout
- `src/lib/brief.ts` — the morning brief's text: workout or rest (projected over your training days), meals with times (with meal swaps), water, what to get ready, weigh-in after 7 days, shopping day
- Light week (deload): settings `deloadUntil`; `applyPlan` halves every exercise's sets (rounded up) while it's on; started from settings or the workout tab card that shows when the gaps report says it's due; no "+kg" tip during it
- Body fat from the tape: `navyBodyFat` in weight.ts (US Navy method; men waist+neck, women +hips; needs sex and height from the calculator), shown with the measurements, one tap to use it in the calculator
- Spreadsheet export: `src/lib/csv.ts` (pure CSV builders with a BOM for Excel: sets, body) + `src/components/ExportSheet.tsx` (settings → صدّر لـ Excel), shared with `shareText` in backupIO
- Progress photos show the body around their date (`bodyOn` / `nearestBefore` in weight.ts: weight, waist, body fat), and the compare view shows the difference
- `src/lib/dates.ts` — every general date helper (`dateKey`, `weekdayOf`, `addDays`, `daysBetween`, `weekStart` (Saturday), `addMonths`, `monthCells`); dates are local YYYY-MM-DD keys, never `toISOString().slice(0, 10)` (that's the UTC day)
- `src/lib/schedule.ts` — workout order: one continuous sequence through `PROGRAM`, not fixed weekdays. The workout tab opens on the one after your last session; missed and rest days don't move it. A program day's id is still `Day.weekday` (logged rows keep it), and plan weekdays only set the weekly attendance/volume target

## Commands
- `npx expo start` — run
- `npm test` — unit tests for pure logic (`src/lib/logic.ts`, progression, `src/lib/dates.ts` (incl. DST and time zones), color, `src/lib/gaps.ts`, `src/lib/shop.ts`, `src/lib/energy.ts`, `src/lib/schedule.ts`, backup, restore safety, weight, journal, plates, summary, programEdit, brief, csv, settings, reminders, stores, records, storage contract, data integrity incl. videos and alternatives)
- `npm run typecheck`
- `npx expo install <pkg>` — always, for SDK-compatible versions
- `npm run update` (`scripts/update.sh`) — the owner's update on the Mac: when there's an `origin` remote, fetch, stash local edits (package-lock), switch to `main` tracking origin/main, fast-forward (local commits kept on a `backup-…` branch); with no remote it skips that; then `npm install`; `-- --build` first runs `npm run typecheck && npm test` and stops if either fails, then re-prebuilds when package.json/app.json changed and installs the release build
